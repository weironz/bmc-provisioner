# BMC Fleet Console 设计方案

## 目标

将现有 `bmc-provisioner` 从 BMC 初始网络配置工具演进为面向运维人员的裸金属 BMC 管理控制台。操作员能够按机房、集群与服务器筛选资产，选择多台设备后批量执行 Redfish 命令，并在单机层面查看硬件健康与资源摘要。

产品展示名称为 **BMC Fleet Console**；现有仓库名、更新通道和包标识在第一阶段保持兼容。

## 用户与核心路径

| 使用者 | 高频任务 | 首期体验 |
| --- | --- | --- |
| 值班运维 | 判断哪个集群发生异常 | 总览健康卡片、集群状态和异常 BMC 数 |
| 集群管理员 | 对一组服务器开机、关机或重启 | 进入集群，筛选、多选、确认并批量下达标准 Redfish Reset |
| 硬件运维 | 核验一台机器的硬件状况 | 从列表打开单机监控抽屉，查看功率、温度、CPU、内存、磁盘与健康 |
| 交付工程师 | 批量初始化新控制器 | 在独立的 Lessor 工作区发现候选、批量改密与配置 IP |

## 信息架构

```
独立的 BMC Fleet 控制台
├── 集群卡片 → 集群工作台
│   └── BMC 列表 → 单机监控抽屉
├── 全部设备
│   └── 筛选 / 多选 / 批量操作
├── 集群
└── 凭据档案

独立的 Lessor 初始化工作区
├── 批量初始化（发现候选、改密、IP 配置）
└── Lessor 设置
```

当前数据模型已经有 `scopeName`、`cluster` 与 BMC 清单。第一阶段将 `scopeName` 作为机房/发现域标签，并将 `cluster` 作为运营视图的主要分组；第二阶段再增加显式的数据中心、机柜、标签和 RBAC 数据模型。

## Lessor 与 BMC Fleet 的运行时边界

这是两个相邻但独立的工作流：

- **Lessor 初始化**：只在操作员进入“批量初始化”并主动刷新时调用 Lessor，用于候选 BMC 的发现、首次改密与 IP 配置。
- **BMC Fleet**：启动、总览刷新、集群、设备工作台、监控与 Redfish 操作只读取本地已纳管 BMC、凭据档案和集群数据，并直接访问目标 BMC 的 Redfish API；绝不调用 Lessor，也不读取其地址或作用域设置。
- Lessor 成功完成配置后可以把 BMC 记录到本地清单；这只是一次导入结果。后续 Fleet 管理不需要 Lessor 在线，也不回写 Lessor、DHCP 或 BMC 网络配置。

## Redfish 能力边界

第一阶段实现只读的标准资源汇总，以及已存在的安全电源控制：

- `ComputerSystem`：电源状态、名称、型号、序列号、CPU/内存/存储资源链接；
- `Chassis/Power` 与 `Chassis/Thermal`：功率和温度（厂商未暴露时显示“未提供”）；
- `Processors`、`Memory`、`Storage/Drives`：核心数、内存容量、磁盘数与总容量；
- `ComputerSystem.Reset`：只展示 BMC 自己声明的可用动作，批量执行沿用显式证书信任和并发限制。

不在首期伪造 CPU 使用率、带宽或磁盘 IOPS；这些值只有在厂商支持 Telemetry Service 或 OEM 指标时才应提供。

## 视觉方向

参考 GreenStor 官网的“白色工业设备展厅 + 石墨文字 + 明亮绿”语言，但不复制其页面、文案或商标。控制台采用：

- 雾白主画布、钢灰分隔、石墨标题，表达硬件与可靠性；
- 绿色作为可执行与健康状态强调色，琥珀/红色只用于告警与危险操作；
- 紧凑、可扫描的控制台密度，避免营销式大横幅；
- 自有几何方位标志，表达“设备节点与控制面”，而非复用 GreenStor 标志。

## 分期与验收

### 第一阶段：可用的管理控制台（本次开始实现）

1. 更名为 BMC Fleet Console，并建立总览、集群入口和多选设备工作台。
2. 保留已纳管 BMC、集群、凭据、证书信任和批量电源接口。
3. 增加 Redfish 设备遥测汇总 API；桌面端启动后及每个自动采集周期后台读取已配置凭据的 BMC，单机监控只展示最近一次采集结果。
4. 完成构建/类型检查与 Redfish mock 测试。

### 第二阶段：可运营的监控

1. 将内存中的定时采集扩展为历史存储，展示趋势、阈值与告警状态。
2. 支持 Redfish Event Service/Telemetry Service，并隔离 OEM 适配器。
3. 加入显式机房、机架、资产标签、批量任务历史和审计日志。

### 第三阶段：完整的 Redfish 操作面

1. 虚拟介质、BIOS、启动顺序、固件、账户和网络工作流。
2. 操作模板、审批和基于角色的权限控制。
3. 多站点代理与集中控制平面。

## 安全约束

- 第一次接触自签名 BMC 时，仍须由操作员确认指纹；监控和写操作都不绕过它。
- 任何批量写入只发送 BMC 在标准资源中明确声明支持的操作。
- API 响应与任务日志绝不返回密码、会话令牌或原始 BMC 错误正文。
